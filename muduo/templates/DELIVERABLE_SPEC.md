# 诊断交付物规范 v1.0 —— 批注式对照阅读器

> 生效：2026-09-10 ｜ 决策来源：01.focus 案例验收（用户确认"交付比原来好多了，作为 1.0 版固化"）
> 模板：`templates/diagnosis_reader_v1.html` ｜ 参考实现：`木铎诊断案例/01.focus.reader.html`
> 铁律依据：13 Reader Language（本规范 §3 即其自查清单）；衔接铁律 2 / 9 / 11 / 12。

## 1. 适用范围与形态

- **适用**：M1/M2/M7 诊断类任务的用户交付物；改写/优化任务的诊断附件。
- **默认形态**：零依赖单文件 HTML 阅读器（`file://` 双击可用、无 CDN、可打印）。
- **降级路径**：用户明确要轻量文本时，输出分层 Markdown（一句话总判 → 关键问题 → 决策区 → 附录），
  **§3 自包含门禁同样适用，不因降级豁免**。
- **产出物分离**：阅读器只承载"诊断＋方案＋清单"；改写成品（新标题定稿/回帖串/金句卡）按用户
  选择的选项另行产出，避免诊断物无限膨胀。

## 2. 结构规范（三视图）

```text
工具栏   视图切换 ｜ P0–P3/资产 筛选 ｜ 待拍板入口 ｜ 打印
视图一   左右对照（默认）：左＝逐字保真原文，右＝诊断卡流；双向定位
视图二   原文批注：全宽沉浸，角标开/关内嵌批注卡，J/K 跳转
视图三   诊断报告：结论屏 → 决策区 → 附录折叠区
抽屉     施工清单（可勾选，localStorage 记忆，需拍板项标"先拍板"）
打印态   自动合并为"原文（批注全展开）→ 报告"顺序版式
```

- **批注三色**：红＝问题（挂 P0–P3）｜黄＝待改进（轻度）｜绿＝资产（金句/好案例/可信信号，
  必须给出放大利用动作）。诊断不只挑刺，资产标注是规范的一部分。
- **诊断卡骨架（统一 schema）**：序号＋类型徽章＋影响层 → 原文引文 → 现象（问题卡）/
  为什么是资产（资产卡）→ 机制（中文名＋原名＋等级＋边界）→ 修复动作（删除线/插入线，
  一律"〔建议·待你确认〕"，需拍板加"需拍板"徽章）。
- **结论屏**：一句话总判＋行为链得分条＋关键问题 ≤3＋推荐路径＋待拍板列表。
  行为链得分须注明数据可得性（无后台数据时写"结构层面风险评估"）。
- **决策区**：候选对比矩阵（✓/半/✗ 逐格）、结构提案、选项对比表（范围/作用层/前提风险）。
- **附录**（折叠）：符号与三色说明（固定文案，逐份保留）／评分全表／机制全表／反模式走查／
  边界风险。铁律要求的"边界与风险槽位""下一步选项槽位"在阅读器中分别落在附录风险折与决策区，
  不可省略。

## 3. 自包含门禁（铁律 13，交付前逐条过）

诊断交付物写给**诊断发起人**，不写给模型。四条全过才算完成：

1. **零内部词汇**：面向用户的正文不得出现 adapter 字段名（title_role 等）、模式代码（M1–M7）、
   节点/反模式编号（AP-LF-xxx）、内部状态词（MEMORY_BASED/Re-outline/Pass 2）、英文置信标签
   （HIGH/MEDIUM/LOW）。置信用中文"高/中高/中低"。
   **合法保留**：机制研究原名（阅读说明已解释"保留原名避免翻译歧义"）；被诊断原文自带的技术词
   （需回原文定位）；L1–L4/P0–P3/A–E（阅读说明有定义）。
2. **引用即内联**：每个被点名的机制、反模式、平台概念，解释当场写全——
   `中文名（English）（等级）＋ 在本文如何起作用 ＋ 一句适用边界`；复核清单机制（peak_end_rule /
   cognitive_fatigue / loss_aversion / nudge / choice_overload）另带修正状态。
   禁止任何形式的"详见知识库/源码/前文某内部文档"。
3. **阅读说明在场**：附录"如何阅读本报告"折叠区保留（含三色批注含义），开头结论屏可直达。
4. **术语清查**：交付前对成品 grep 一遍：`AP-|adapter|title_role|sharing_mechanism|
   content_lifecycle|interaction_signals|comment_role|risk_factors|opening_role|warrant|
   qualifier|overclaim|Re-outline|Pass 2|MEMORY|VALIDATED|HIGH|MEDIUM|LOW|M[1-7]｜thread|
   quote|feed|CTA|Hook`——逐个命中裁决：合法保留（原文词/机制原名/已解释）或改写。
   **清查结果留痕**（在会话中列出命中与处置，对应铁律 11"口说不算完成"）。

## 4. 证据卡格式（机制引用的标准颗粒）

```text
主机制：中文名 English <等级徽章> ＋ 在本文作用一句 ＋ 边界：适用条件/不适用条件
修正机制：另加"修正：行为层稳定，××旧解释已被 20×× 年重复研究推翻，只取行为层"
次要机制：至少最小单元（中文名＋等级＋半句边界）
分析框架（如论证结构四件套）：明确标注"是分析框架而非实证效应，不作为机制计级"
```

## 5. Intake 提问（诊断前，衔接铁律 9 三对齐）

动笔诊断前确认（输入可推断时复述确认即可，不可推断时选项提问）：

1. **目标定位**：这篇内容要什么——爆款扩散 / 立框架树权威 / 系列基石 / 引流转化？
   （直接决定行为链加权：立框架型内容"分享/评论触发缺失"降级为 P2–P3）
2. **发布状态与数据**：未发布草稿 / 已发布？有"展示→点击→完读→互动"任一环数据吗？
   **无数据 → 涉及表现预测的结论自动封顶"中低置信"并在结论屏声明。**
3. **受众圈层**：主受众是谁（圈内/圈外比例）？——影响行话门槛与入口词判断。
4. **投入预算**：只改卡片层 / 愿意动结构 / 逐句精修？——决定选项默认推荐。
5. **禁忌**：身份表述、数据披露、平台选择有没有不可动的地方？
