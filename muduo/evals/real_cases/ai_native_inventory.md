### 2.2 方法论框架 / 命名概念（全量）

**理念层（篇1）**
1. **"人辅助AI"（人工辅助AI编码）**——AI 是执行者、人是决策者的新范式，与"Copilot 式 AI 辅助人"相反。
2. **"AI牧羊人"**——人通过高质量 Prompt、严谨流程和 Checklist 驱赶与约束 AI，而非被 AI 裹挟。
3. **"AI 作为模拟团队"**——AI 是"一个超大规模、超高速的虚拟开发团队"，人扮演项目经理+架构师+测试组长。
4. **数据驱动/视觉驱动/契约驱动**——从 PRD 到 DB、从 UI 到 API、从 API 到代码的三段驱动脉。
5. **"递归辅助"**——AI 生成代码，AI 按人类定义的规则审查，人做最终决策。

**输入层（篇2）**
6. **情景化开发路径**——项目启动先选路：情景 A 体验驱动型（UI/UX First，UI 稿反推数据库）；情景 B 逻辑驱动型（Data/Logic First，数据模型是"宪法"）。
7. **AI友好型PRD（四特征）**——全局术语表（建立"巴别塔"）、EAR 表（数据模型前置）、逻辑真值表（Truth Table 降维替代流程图）、UI 绑定（功能点关联设计稿）。
8. **"从文学作品到结构化指令"**——PRD 不再是写给人看的文档，而是"提示词前置包"。
9. **用 AI 质检 PRD（"找茬提示词"）**——写代码前把 Bug 消灭在文档里。

**设计层（篇3-5）**
10. **融合驱动**——DB 设计强制双核输入（PRD+UI），每个字段回答三问：PRD 依据？UI 消费场景？冲突怎么权衡？
11. **显性化权衡声明（Explicit Trade-off）**——反范式等关键决策必须输出"决策日志"三段论：决策点/收益（UI侧）/代价（DB侧）。
12. **"无场景，不索引"**——说不出"服务谁"的索引不许创建。
13. **AI互评机制（AI审核AI）**——Auditor AI 拿 Checklist 给 Builder AI 找茬，打破"上下文致盲"（篇3 首提，篇8 展开）。
14. **功能切片（Functional Slice）**——垂直的、端到端的、用户可感知的最小价值单元（区别于水平的前后端任务拆分）。
15. **边界声明与强制溯源（"出身证明"）**——切片必须标注对应 PRD 章节/UI 区域，填不出依据即暴露幻觉。
16. **API需求 ≠ API设计**——消费侧视角（UI 要什么）与供给侧视角（我有什么表）必须先需求后设计。
17. **最小化原则（Minimum Viable API）+"理由先行"**——UI 用不到的字段剔除，保留的字段必须写理由注释。
18. **黄金30分钟**——蓝图阶段产品+技术+前端 30 分钟审核两份文档，"在源头掐灭风险"。
19. **数字化宪法**——静态契约（全局 OpenAPI）+动态剧本（核心业务时序图）。
20. **作战地图**——AI 自主识别复杂业务流程并输出 Mermaid 时序图；后端看伪代码、前端看调用时机、测试看用例路径。
21. **从"沟通驱动"到"规约驱动"**——把管理精力从促进沟通转向定义规约。

**执行层（篇6-7）**
22. **No Mock, Just Deliver**——AI 同一会话生成前后端，联调概念不存在，Mock 是伪需求。
23. **按模块分治（领地意识）**——以业务模块为单位垂直切分（一人包干前后端），跨模块靠契约文档，冲突点只剩公共组件。
24. **全上下文端到端开发指令（上下文"五重奏"）**——业务目标/视觉约束/数据地基/交互契约/执行剧本五维信息拼装投喂。
25. **高保真复现模式 vs AI自主设计模式**——C 端核心页"严格复现"，标准化后台"自主设计"。
26. **AI设计规范（Design System Prompt）**——系统级前置指令，让不同 AI 会话生成的界面风格统一 90%+。
27. **精装修（Refinement）**——人类职责三合一：Reviewer/Tuner/Security Guard。
28. **对话式修正**——永远不让 AI 的上下文断裂："让 AI 去改代码，你只负责提要求。"
29. **垂直切片架构（Vertical Slice Architecture）**——按功能物理聚合代码目录，给 AI 无噪声上下文（注意与 #14 同名不同义）。
30. **主干开发+短生命周期分支（领地隔离/极速合并）**——分支存活 2-4 小时即合并，尽量新增文件少改公共文件。

**质量层（篇8）**
31. **LGTM综合症**——Reviewer 面对海量 AI 代码的审美疲劳式放行。
32. **"自信的幻觉"**——AI 代码格式工整、注释清晰的"漂亮外表"欺骗人类。
33. **自动化测试工厂**——单元测试"伴生"生成（覆盖率 90%+）+基于 OpenAPI 契约自动生成集成测试（"自动化刑具"）。
34. **判例法官（The Judge）+ 规则制定者（The Legislator）**——人类裁决 AI 审查的误报/漏报，并通过改 Checklist"编程"AI 行为。

**迭代层（篇9）**
35. **五维冲突模型**——需求逻辑/数据结构/API契约/代码实现/用户体验五维影响评估。
36. **AI时代的海恩法则**——上下文遗忘、隐性依赖、破坏性变更三重隐患。
37. **先诊断，后手术；先契约，后实现**——迭代总纲。
38. **增量更新SOP**——活的 PRD 打补丁（[v1.1]标记）→ 迁移脚本（含回滚）→ 靶向回归测试 → 端到端实现。
39. **靶向测试 / AI时代的TDD**——把影响评估报告喂给 AI 先生成回归测试，再写业务代码。
40. **Go / No-Go 矩阵**——低/中/高风险红绿灯决策表。

**维护与进化层（篇10-11）**
41. **文档腐烂 / 剪刀差 / 认知错乱**——代码跑到 V1.5、文档停在 V1.0，AI 被喂错上下文。
42. **基线重建（Baseline Reconstruction）**——文档重新对齐代码现状的必修工程。
43. **业务线索驱动（Business-Clue Driven）定向同步**——人只报"业务改了什么"，AI 做"代码考古"（全栈侦探/定向调查令）。
44. **数字孪生**——文档是代码的数字孪生，文档是喂养 AI 的燃料。
45. **双环学习（阿吉里斯）**——单环修 Bug，双环改产生 Bug 的规则本身。
46. **问题模式库（The Problem Pattern Library）**——AI 可读的结构化知识库：现象（Bug）vs 本质（问题模式），词条关联受影响的 Prompt 与 Checklist，经 RAG/动态拼接注入后续生成。
47. **内循环/外循环**——代码层修复与流程层进化两个咬合齿轮。
48. **基因工程师**——人编辑流程"DNA"（Prompt/Checklist）而非救火。
49. **系统自产生抗体**——N+1 进化闭环后，"团队再也没有出现过N+1问题"。
50. **边界在"规约"**——大结局总纲：人机边界从"代码"重定义为"规约"。

20. **五维冲突模型评估 Prompt**："不要急着写代码，先告诉我：如果我们这样改，会炸掉什么？"（篇9）
21. **《技术影响评估报告》+ Go/No-Go 红绿灯矩阵**：🟢 Go 直接开发 / 🟡 Caution 强制回归测试 / 🔴 Hold 架构评审（篇9）。

24. **靶向回归测试生成指令**：把《技术影响评估报告》喂给 AI，针对受影响模块旧功能生成回归测试，"在写业务代码之前，先准备好这套测试代码"（篇9）。

26. **问题模式库 JSON 结构**：Pattern ID/标题/根因分析/触发场景/解决方案模式/**关联流程资产（影响的 Prompt + 影响的 Checklist）**，经 RAG 或动态拼接注入后续任务（篇11）。
27. **Bug 进化四步 SOP 提示词组**：根因分析与模式抽象→影响范围定位（"该改哪些 Prompt/Checklist"）→流程资产迭代重写→闭环验证（同步给 Auditor AI）（篇11）。

### 3.2 文中明确指出、至今仍存在的问题（"不过时的是认知"证据链）

1. **需求表达质量是第一瓶颈**："要想让AI精准干活，我们必须先解决'输入质量'的问题。"（篇2）；"拒绝垃圾输入，是通往高效研发的第一张门票。"（篇2）——vibe coding 时代"会把话说清楚"更稀缺，依然成立。
2. **人"说不清楚"是普遍短板**："管理能力和精准表达能力普遍偏弱……甚至连如何与AI对话，说出自己想要做什么都成问题。"（篇1）——与今天"会用 AI 的人与不会用的人拉开差距"的讨论同构。
3. **幻觉的裁决权在人**："当AI开始'脑洞大开'时，是产品经理，而不是AI本身，来决定'哪些幻觉可以保留，哪些必须扼杀'。"（篇1）；"幽灵表/幽灵字段"审查（篇3）；"出身证明"溯源法（篇4）——今天 agent 更强，幻觉形态变了但"由人裁决"未变。
4. **验证成本与生成成本的剪刀差**："生成代码的成本无限趋近于零，但理解和验证代码的成本依然昂贵。"（篇8）——2026 年关于"代码越多审查越贵"的主流讨论完全同题。
5. **改旧代码的风险（AI 缺全局痛感）**："因为AI缺乏'全局痛感'。"（篇9）；"AI倾向于'重写'而非'扩展'"（篇9）——今天 agent 在遗留代码库上翻车仍是头条话题，此篇最具"至今仍存在"的传播力。
6. **文档腐烂/上下文漂移**："文档与代码的'剪刀差'，构成了AI的'认知错乱'。"（篇10）；三大症状（字段改名/漏租户隔离/漏风控拦截，篇10）——今天任何接了过期上下文的 AI 会话都在复现。
7. **规约先于沟通**："沟通总会有损耗，但规约是无损的。"（篇5）——与 2026 兴起的 spec-driven development 思路互证。
8. **人的角色上移**：判例法官+规则制定者（篇8）→ 基因工程师（篇11）→"边界在规约"（篇11）——今天"AI 时代工程师做什么"的核心议题，作者 2025 年已给出完整答案框架。
9. **组织与并行冲突**：按模块分治、领地隔离（篇6/篇7）——今天多 agent 并行开发依然要解决同样的问题。
10. **安全与性能盲区**："AI对安全的理解通常停留在表面"（越权/注入，篇7）；"只管实现，不管性能"（N+1，篇7/篇11）——2026 年依然是人工介入的底线领域。

1. **导语与正文的驾驶比喻自相矛盾（篇1）**：导语说"AI不该是副驾驶，AI才是驾驶员"（第 8 行），正文说 AI 是"新手驾驶员"、人是"导航仪/牧羊人"（第 16、81 行）。同一比喻两种立场，读者会抓包；且导语句若单独截出做 X 金句，恰好与作者真实主张相反。打包前必须统一口径。

### 5.1 最强叙事主线（基于材料实际内容）

**"2025 年，我们用 5 个月手搓了一整套'人辅助AI'的流程机器；今天回头看，其中一半'手艺'已被模型和工具的迭代吞掉——但那台机器所对抗的问题，一个都没有消失。"**
