# Workflow: Postmortem（传播复盘）

用途：Mode 6。给定内容与实际数据，反推哪个行为环节出了问题。**核心纪律：先排除外生变量，再归因内容。**

## 输入
内容（标题/正文/脚本）、平台、数据（曝光/点击/阅读/停留/赞/藏/评/转/关注/转化，有多少给多少）、目标与预期、发布背景（时间/账号状态/投流）。

## 流程
1. **数据结构化**：把数据对齐到行为链：
   曝光→点击（CTR）→阅读（读完率/跳出）→深度（停留/回访）→互动（赞评藏）→
   传播（转发/关注转化）→转化。
   缺哪层数据就声明哪层无法诊断，不脑补。
2. **外生变量排除**（"不要改"能力，必须先做）：
   - 分发环境：平台政策/算法调整期？账号是否处于限流/扶持期（cold_start_dynamics）？
   - 时机：是否撞热点/节假日/竞品大事件？
   - 受众错配：发布时间与目标人群在线时段？内容被推荐给了非目标人群？
   - 投流：付费流量占比？付费流量质量（高曝光低互动=人群不准）？
   - 结论先行标注：哪些差异能用外生变量解释。
3. **漏斗定位**（按相邻比率，不猜单点）：
   - CTR 低 → attention 层：title/cover/curiosity/relevance（读 adapter 的 title_role/cover_role）
   - CTR 高、读完率低 → expectation mismatch（标题-内容兑现断裂）/ cognitive load / 开场无 scent
   - 读完率高、互动低 → 内容"看完就走"：缺 comment trigger/identity signal；或内容好但无表达位
   - 收藏高、转发低 → Personal Utility 强 Social Currency 弱：补身份表达/转发言口（identity_signaling）
   - 转发高、涨粉低 → 单篇传播≠账号价值预期：定位不连贯（账号层 diagnosis）
   - 全链路好、转化低 → friction/信任/offer 问题，不是内容问题
4. **机制归因**：对定位到的环节，从 mechanism 库取 2-3 个候选机制，
   用数据方向 + 内容事实交叉验证（例：读完率低 + 标题承诺强 → expectation violation 优先于 cognitive load）。
   **多机制竞争**：允许机制同时反向（Attention↑ Trust↓ Share↑ Conversion↓）——
   不要强行找一个万能解释；每个归因标注 causal_status（observational/case_inference 等，
   复盘数据几乎永远是观察性的，禁止写成确定因果）。
5. **对照检查**：与该账号历史内容对比（同题材 vs 跨题材），分离
   "内容问题"与"账号问题"；有同类爆款对照更有说服力。
6. **反事实检验**：问"如果改了 X，数据会怎样"——检验归因是否可证伪。
   不可证伪的归因（"就是不行运"）不得写入结论。
7. **输出**：环节定位 → 归因（带证据等级与置信度）→ 可执行修正 → 观测指标。
   **短期 ≠ 长期**：修正建议必须检查短期表现与长期价值的冲突
   （高 CTR→低信任 / 高病毒→品牌损伤 / 高互动→社群毒性，）。

## 输出格式
```text
## 数据链概览
（各层比率 + 缺失层声明）
## 外生变量排除
（结论：排除/不能排除，理由）
## 瓶颈环节
定位：曝光→[点击]→阅读...（标注最短板）
## 归因分析
1. [机制] （证据 x，置信度：高/中/低）—— 支持数据：...
   替代解释：...（必须给≥1个）
## 修正建议
（对应 Recommendation Schema）
## 下次观测指标
## 复盘边界
（本次结论适用的范围；数据不足处的声明）
```

## 禁止
- 用单点数据直接改文案（先定位环节）
- 把相关性当因果（数据相关≠机制成立）
- 幸存者偏差复盘（只分析爆款不分析哑弹=无结论）
- 归因给"算法针对我"这类不可证伪解释
